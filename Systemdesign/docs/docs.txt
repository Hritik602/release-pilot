**2. Programming Architecture Pattern**
Yes, web SaaS also needs architecture patterns.

In mobile you use:

```text
MVVM + Repository + Retrofit Service
```

For our web app, the similar pattern is:

```text
UI Components
→ Server Actions / API Routes
→ Service Layer
→ Repository / Prisma Queries
→ Database
→ External Provider Clients
```

Example:

```text
Dashboard UI
→ getReleaseDashboard()
→ releaseService.getDashboard()
→ releaseRepository.findCurrentRelease()
→ Prisma/PostgreSQL
```

For integrations:

```text
GitHub Sync Job
→ githubService.syncRepository()
→ githubClient.fetchPullRequests()
→ releaseRepository.savePullRequests()
```

Best pattern for us:

```text
Module-based clean architecture
```

Each business area gets its own module:

```text
modules/releases/
  release.service.ts
  release.repository.ts
  release.types.ts
  release.validators.ts
```

This is effective because:

- UI stays clean
- Business logic is reusable
- Database logic is not scattered everywhere
- Easier to test
- Easier to move backend to NestJS later if needed

Without pattern, the project becomes messy fast:

- API routes contain too much logic
- UI directly talks to database
- integration logic gets duplicated
- scoring rules become hard to change
- security checks get missed

So yes, we should use a pattern, but not over-engineer.
